# 28号基线的长录音容量与位宽核算

2026-10-31，只读检查28号工程、核心板原理图及Sipeed官方参数；没有修改RTL、IP或约束，没有操作开发板。

## 建议交付上限

采用 **5分钟**、`MAX_SAMPLES=14648438`。采样率仍为`50000000/1024=48828.125 Hz`，单声道PCM16。实际最大时长300.00001024秒；声音、采样时基、DDR时钟和IP均不必为延长录音而更改。

| 项目 | 5分钟配置 |
| --- | ---: |
| 最大PCM样本 | 14,648,438 |
| 原始有效字节 | 29,296,876 |
| 256bit BL8块数 | 915,528 |
| 分配字节（含最后补零） | 29,296,896 |
| 最后一个块的app地址（32bit word单位） | 7,324,216 |
| 最后块有效PCM lane | 6 |
| 最后块补零lane | 10 |
| 有效样本计数的最低位宽 | 24 bit |
| 已请求块计数的最低位宽 | 20 bit |

正式实现可统一使用32bit样本／块计数，仍将上限限定为5分钟。现有29bit app地址足够，不必扩大物理端口。读地址若由块数拼接，必须消除原18bit块计数相关的硬编码；并检查最终地址转换没有中间截断。

## 物理资料与IP配置的差异

本地`05_硬件资料/hardware_reference/som_138k_30353.pdf`第3页列出两颗`MT41J128M16JT-125:K`。按128M×16组织，每颗为2Gbit，合计512MiB。该页是本地官方原理图，不构成本次对实物芯片批次的重新识别。

[Sipeed当前官方硬件参数](https://wiki.sipeed.com/hardware/en/tang/tang-mega-138k/mega-138k)列1GB DDR3（512MB×2）。现有`ip/generate_ip.tcl`显式配置Row15／Col10／Bank3／DQ32，也对应1GiB逻辑空间。旧图与当前官网可能反映不同批次或BOM，不能仅据IP配置就断言当前实装且已验证1GiB。

本轮录音只使用约27.94MiB、低于32MiB的低地址空间；即按旧图较小的512MiB核算也仅约5.46%。因此5分钟不依赖确认高地址全容量，且无需修改已工作的DDR geometry／PHY／PLL/IP。该容量推算不是对整块DDR全地址实测。

## 现有软件限制

`pcm_clip_controller.v`当前21bit样本计数与18bit读块计数不是物理DDR容量上限。21bit样本约42.95秒就会回绕，不能只改MAX_SAMPLES。

`ddr_audio_bridge.v`的请求地址保持29bit，没有旧30秒专用的地址范围截断。启动自检16个位置覆盖约3.93MiB，但它不保留一块禁止录音使用的区域：自检通过后录音覆盖这些地址是现有设计。返回实时后不重新自检，直到全局复位；全局复位同时使临时录音失效。

延长后应覆盖旧边界2^21样本、跨新增高地址位、最后6有效lane、停止后提交、回放末样本、暂停／继续及重录。启动自检的原覆盖范围不等于5分钟记录空间已实板验收。可另加低32MiB内的高地址非别名自检；若修改自检地址步长，须同步D3的地址与index关系解析，不能保留旧`index*65544`判断。

## LCD必须同步扩大

现LCD使用32bit顺序除法，5分钟的两个中间值已经溢出32bit：

- `14648438<<10 = 15000000512`，需要34bit。
- `14648438*432 = 6328125216`，需要33bit。

建议统一40bit顺序除法、16bit百分秒，5分钟上限30000cs。四次40bit除法若保留每次1拍加载，计算延迟为`4*(40+1)=164 clk`，不再是原132clk；仍远小于一个LCD帧。前后状态和时间必须保持原子发布。

时间显示使用`MM:SS.cc`，例如`05:00.00`，共8个ASCII半格。原格式`30.00秒`占7格，因此time_token范围及row3/row4定位都要调整；现37半格宽度足够。无录音时间可用`--:--.--`。录满文字同步改成5分钟。

## UART和工具

采用32bit L/P快照时建议新增协议版本并用8hex传样本数；当前R5的6hex虽勉强可装5分钟，但RE仍将首位限定为[01]、解析上限仍1464844。所有RTL快照宽度、字节位置、包长、PowerShell过滤、Python解析、状态打印与离线自检均须同步。若只将R5的L/P各扩2hex，其余字段不变，状态包由113变117字节；D3仍164字节。实际新协议若再加入灯环参数，应按真实字段重新计算，不套旧长度。

## 动态灯环余量的数值边界

调试版应保存一次校准所得的`calibrated_baseline`，随后以当前旋钮余量计算`gate=clamp(2*stored_baseline+margin,64,65535)`。现有baseline组合wire在校准后仍包含当前窗口均值，不能直接拿来动态重算门限，否则讲话会把门限跟着抬高。

若余量允许负数，使用至少18/19bit的有符号中间和、明确有符号的上下限比较，再取低16bit。避免负值先变成无符号后被错误夹到65535。`-256`的绝对值是正256，不能放入有符号9bit正数；显示可用unsigned9bit或扩10bit。

范围`-256..+255`可作为有限调试范围，但不保证覆盖任意底噪。例校准均值B=512，最小门限仍为768，SK9822在原曲线和`level>>1`量化下首次非零约需均值800。要把门限调到接近B，通常需要margin约为`-B`。若希望一次调试覆盖更广背景，可考虑`-2048..+2047`或`-4096..+4095`，并结合粗／细步进；是否采用由主集成决定。

调余量只改变显示电平表，不应重置音频、打断回放、改变录音PCM或重新测底噪。显示余量、实际门限和当前均值有助于现场选值；原亮度曲线、固定64下限与自校准倍数仍保留。

软件核算与离线验证不代替5分钟实物录放、最终现场亮度、音质或整机连续运行验收。
